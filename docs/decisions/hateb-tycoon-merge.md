# hateb-tycoon を feed-tycoon に統合しない(2026-10-01)

## 決定

hateb-tycoon と feed-tycoon は統合せず、別のアプリのままにする。`sources.json` の `hateb-it` は、はてブ以外のソースと同じ1ソースとして残す。

## 理由

- はてブ9カテゴリ×300件(約2.7MB・高頻度更新)が `data/feed.json` に混ざり、更新頻度が低く件数も少ないブログ系ソースが重い方に引きずられる。
- ソース別の保持上限、並び替え(ブクマ数順など)、カテゴリタブ、URL の重複排除といった課題は、はてブを混ぜることで初めて生まれる。
- hateb-tycoon は既読・NEW バッジ・並び替え・オフライン事前取得まで作り込まれていて、feed-tycoon で作り直すコストの方が大きい。
- 取得時間は問題にならない(4ソースで約30秒、逐次+1秒 sleep。100ソースでも約5分の見込み)。

## 再検討するとき

本人は「いずれまた統合したくなる」と見込んでいる。話が出たら蒸し返しではなく再開として扱い、次の差を埋めるところから始める。

1. ソース別の保持上限(feed-tycoon は1ソース100件固定、hateb-tycoon は1カテゴリ300件・14日)
2. 並び替え4種(更新日時 / 取り込み順 / ブクマ数 / タイトル。feed-tycoon は firstSeenAt 固定)
3. カテゴリタブと「全て」での URL 重複排除
4. NEW バッジ(新着コメント)の挙動を揃える

既読 Gist の移行は不要(統合後から数え直せばよい、と本人が言っている)。フィルタ設定は共有 Gist(`tycoon-filter-*.csv`)で既に両アプリ共通。
